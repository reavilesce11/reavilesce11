## Public work

### [Reloop — orchestration for two AI coding agents](https://github.com/reavilesce11/reloop)

Two AI assistants work the same task and audit each other: one proposes, the other reproduces the result and attacks it, and nothing reaches the filesystem without my approval. It runs on `127.0.0.1`, stores no API keys, and keeps Markdown as the source of truth — SQLite is a disposable index that rebuilds from disk.

The interesting part is what measuring it revealed. The first working version sent 49,240 characters of context on every call against its own 32,000 ceiling, so the safety branch fired every time and forwarded the full payload anyway. The browser re-downloaded the whole transcript every 2.5 seconds, including while idle. Sessions were resumed forever until one reached 343k tokens and could no longer answer inside the timeout — and could never retire itself, because rotation only ran after a successful call.

| | Before | After |
|---|---|---|
| Context per call | 49,240 chars | **11,178** |
| Warm call, context unchanged | full package | **104 chars** |
| Idle traffic per 12s | ~2,810 KB | **5.2 KB** |

138 automated tests, including a regression test for each of those failures.

### [Metadata Quality Pipeline](https://github.com/reavilesce11/metadata-quality-pipeline)

A method demonstration on synthetic data — I wrote both the malformed records and the rules that catch them, so treat it as a sample of how I build and test, not as a hard problem solved.

![Quality dashboard generated by the pipeline from synthetic episode data](https://raw.githubusercontent.com/reavilesce11/metadata-quality-pipeline/main/docs/dashboard.png)

It ingests messy records, preserves the raw values, normalizes fields, applies deterministic quality rules, routes ambiguous cases to a human review queue with an explicit reason, stores an audit history in SQLite, and generates SQL reports and an HTML dashboard. The point is what it refuses to guess: **10 records → 3 accepted, 5 sent to review, 2 rejected, 8 documented issues.**

Eighteen automated tests. Five of them test the publication guard itself: three force it to reject a committed secret, a local path and a forbidden filename; one confirms an ordinary file produces no findings; and one proves the guard does not exempt its own test suite. GitHub Actions runs everything on Python 3.11 and 3.12 on every push.

## How I work

Evidence before conclusions. Root cause before fixes. Small, reversible changes, one logical change per commit. Hypotheses are marked confirmed, refuted, partial or indeterminate — killing a false hypothesis counts as progress. A small sample is a trend, not a law. Every number cites its source.

I use AI assistants to generate hypotheses, examine counterexamples, review changes, and summarize evidence. Their output is never accepted on authority: I verify it through tests, source evidence, reproducible runs, and human review.
